# إشعارات الشات — رواق 1.7

## المنفذ

- FCM للشات الخاص في الاتجاهين، وجروبات الحصص؛ دون إشعار للمرسل.
- إشعار ولي الأمر مستقل عن الطالب وعن أي ولي آخر. جروب الطلاب لا يرسل لأولياء الأمور.
- فحص التسجيل وحالة المجموعة والطالب والمدرس والربط الحالي عند إنشاء الإشعار وعند تسليمه، مع فحص صلاحية الجلسة ودور الجهاز.
- حفظ سجل الإرسال داخل نفس عملية حفظ الرسالة. إعادة محاولة إرسال نفس الرسالة لا تنشئ إشعارًا ثانيًا.
- نص شاشة القفل عام: «عندك رسالة جديدة. افتح المحادثة للاطلاع عليها.» لا يخرج محتوى الرسالة أو اسم الطالب إلى FCM.
- بيانات الإشعار: type وeventId وtenantId وrecipientId وconversationId فقط. الموبايل يتحقق من الحساب والسنتر ثم يجلب المحادثة من API المحمي.
- تسجيل وتجديد توكن الجهاز وفصله عند الخروج. الجهاز يتبع آخر حساب مسجل له، والجلسة الملغاة لا تستقبل تسليمًا جديدًا.
- عامل إرسال مستقل يفحص الانتظار كل 5 ثوانٍ افتراضيًا؛ لا ينتظر مهام الفواتير أو WhatsApp. لا يعمل داخل طلب إرسال الرسالة.
- إعادة استخدام رمز OAuth للخادم إلى قرب انتهاء صلاحيته لتقليل تأخير إشعارات الجروبات.

## إعداد السيرفر

ملف حساب الخدمة **لا يدخل الريبو أو APK**. انسخه يدويًا إلى مسار خاص على السيرفر، مثل `App_Data/firebase-service-account.json` بجوار ملفات التطبيق المنشور، خارج `wwwroot`. مجلد App_Data مستبعد من حزمة النشر ويحافظ عليه إعداد Web Deploy الحالي.

أضف إلى إعدادات السيرفر:

```json
{
  "Push": {
    "Enabled": true,
    "PollSeconds": 5,
    "Fcm": {
      "ServiceAccountPath": "App_Data/firebase-service-account.json"
    }
  }
}
```

يمكن بدل الملف استخدام متغيرات البيئة `Push__Fcm__ProjectId` و`Push__Fcm__ClientEmail` و`Push__Fcm__PrivateKey`. لا تجمعهما مع ServiceAccountPath؛ عند وجوده يكون المصدر المعتمد.

يجب أن يكون حساب الخدمة من نفس مشروع إعداد Android، وأن تكون FCM HTTP v1 مفعلة وله صلاحية الإرسال. بيانات حساب الخدمة المرفوعة من المالك تم استخدامها للتحقق من Google OAuth وتسجيل تطبيق Android وجلب إعداد العميل؛ لم تُضف إلى أي commit. فحص FCM بوضع validate_only وصل إلى تحقق توكن الجهاز؛ هذا ليس إثبات تسليم على جهاز.

لا تحتاج هذه الإضافة migration جديدة. يلزم أن يكون migration الشات السابق `20261029120425_ScopedChat` مطبقًا. نشر الكود على GitHub وحده لا ينشر إعدادات السيرفر أو الملف الخاص.

## الموبايل

مشروع Firebase: `rewaq-15f52`. معرّف Android بقي `com.zeiia.teacher_centers_mobile`. إعداد العميل العام فقط في `config/google-services.android.json` داخل ريبو الموبايل؛ لا يحتوي مفتاح حساب الخدمة. CI يولد موارد Android وخيارات Dart منه؛ يمكن تجاوز المصدر بواسطة Secret `FIREBASE_ANDROID_CONFIG`.

من شاشة الرسائل اختر «إعداد الإشعارات» واسمح بالإذن. الضغط على الإشعار يدعم فتح التطبيق من الخلفية أو بعد الإغلاق. إذا كان حساب أو سنتر مختلف مسجلاً، لا يتم التحويل تلقائيًا. في المقدمة يظهر تنبيه داخل التطبيق؛ المحادثة المفتوحة نفسها تتحدث دون تنبيه مكرر.

iOS مجهز بالكود وصلاحية remote-notification، لكنه يحتاج تطبيق iOS مسجلاً وخيارات Firebase الخاصة به ومفتاح APNs وشهادة provisioning مناسبة. لا تعتبر نسخة Android إثبات تشغيل iOS.

## تحقق الجهاز الفعلي

1. انشر الباك إند مع إعداد الخدمة ثم ثبّت APK 1.7.0+9.
2. سجل الدخول واسمح بالإشعارات، ثم أرسل من حساب آخر في مجموعة نشطة.
3. اختبر الخلفية والإغلاق الطبيعي والضغط على الإشعار، والرفض ثم السماح من إعدادات النظام.
4. اختبر شات ولي الأمر وجروب الحصة وإلغاء التسجيل والخروج وتغيير الحساب.

اختبارات الخادم تغطي النطاق والخصوصية ومنع التكرار والعضوية الحالية وحمولة الإشعار. اختبارات الموبايل تغطي الإذن والتسجيل وتغير التوكن وفتح الإشعار وعزل الحساب والسنتر والخروج. لم يتم ادعاء تسليم حقيقي قبل اختبار جهاز مسجل.

FCM خدمة تسليم بأفضل جهد؛ الشبكة وسياسات توفير البطارية وإذن النظام تؤثر على الوصول، وForce stop من إعدادات Android يتطلب فتح التطبيق مجددًا. السجل الحالي يسجل Sent/Failed/NoDevice؛ فشل الإرسال لا يغيّر حفظ رسالة الشات. إعادة المحاولة التلقائية للرسالة النصية لا تعيد دفع إشعار تم إرساله.

## مراجعة التشغيل وإصلاح تجديد الجلسة — 1.7.1

- تم اختبار SignalR حيًا يوم 29 أكتوبر 2026: تفاوض 200، اتصال WebSocket مصادق، handshake وWatchThread ناجحان، ووصول ChatChanged للطالب بعد رسالة المدرس. نتيجة مستقلة عن الـpolling. هذا لا يثبت تشغيل Firebase على جهاز المستخدم.
- إصلاح استمرار وصول البوش بعد تدوير جلسة الدخول، مع استمرار منعه بعد الخروج أو إلغاء عائلة الجلسة. الموبايل يعيد ربط الجهاز عند تغير session_id.
- GET `/api/v1/devices/status` يعرض حالة تفعيل الخادم وإعداد المزود وأعداد الأجهزة وآخر حالة إرسال للحساب المصادق فقط، دون توكنات أو مفاتيح أو مسارات خاصة.
- صفحة إعداد الإشعارات متاحة من الرسائل والإشعارات، وتوضح فشل تسجيل الجهاز وخدمات Google وقناة الرسائل وحالة السنتر.
- ملف Android حجمه 684 بايت في ملفات المشروع الحالية؛ ليس حساب خدمة. ملف حساب الخدمة المرفوع من المالك حجمه 2373 بايت ويحتوي نوع service_account ومفتاحًا خاصًا. تغيير اسم ملف Android لا يجعله صالحًا للسيرفر. لا تُنشر بيانات المفتاح في المستند أو الريبو.
